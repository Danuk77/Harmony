
## Setting up a video call

Quoted labels describe state of peer.

> A: outgoing

A => B 
```jsonc
{
    "initiate": "videoCallRequest",
}
```

> B: incoming

Either peer can cancel the call by sending:
```jsonc
{
    "type": "reject",
    "terminate": "done"
}
```

Both peers must send this message every 5 seconds to prevent the transaction timing out:
```jsonc
{
    "type": "wait"
}
```

If B accepts the call then B creates an SDP with
+ a video/audio stream, and
+ a data channel named "closeCall" - used by the peer to detect when the peerConnection closes.

B => A
> B: expectSDPAnswer
```jsonc
{
    "type": "acceptAndOffer",
    "payload": {
        // generated by WebRTC
        "type": "offer",
        "sdp": "..."
    }
}
```


> A: ICE

A => B
```jsonc
{
    "type": "answer",
    "payload": {
        // generated by WebRTC
        "type": "answer",
        "sdp": "..."
    }
}
```

> B: ICE

Both peers send ICE candidates to the other:
```jsonc
{
    "type": "ICECandidate",
    "payload": {
        // generated by WebRTC
        "candidate":"...",
        "sdpMLineIndex":0,
        "sdpMid":"...", // optional
        "usernameFragment":"..." // optional
    }
}
```

Transaction ends when a peer times out.

## Sending a message

A => B

```jsonc
{
    "initiate": "message",
    "message": "...",
    "number": 1234 // used to identify messages later. Receiver checks if there is already a message with this id. Integer in the range 0 to 9007199254740991
}
```

B => A
```jsonc
{
    "terminate": "done"
}
```
